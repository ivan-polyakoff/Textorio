# Универсальный МК-бот — архитектура мультипровайдера и мультитранспорта

Идея: одна кодовая база Textorio → много ботов. Любой ИИ-шлюз (GigaChat, YandexGPT,
любой OpenAI-совместимый), любой мессенджер (VK, MAX, позднее Telegram), скиллы и
персонаж — конфигурируются, а не зашиваются.

Статус: дизайн. Реализация по шагам в конце документа.
**Приоритет (09.11.2026): работаем для VK. MAX отложен —Transport max.js и
вебхук-инфраструктура описаны здесь как задел, не реализуются сейчас.**

## Три независимых слоя

```
┌─────────────────────────────────────────────────────┐
│  CORE (движок)                                      │
│  скиллы (пак-файлы) · персоны · интенты · состояния │
│  rate limit · разбиение длинных текстов · logger    │
└──────────────┬──────────────────────┬───────────────┘
               │ контракты            │ контракт провайдера
┌──────────────▼──────────────┐ ┌─────▼──────────────────┐
│  TRANSPORT (мессенджеры)    │ │  AI PROVIDER (шлюзы)   │
│  vk.js (vk-io, Long Poll)   │ │  gigachat.js           │
│  max.js (@maxhub/max-bot-   │ │  openai-compatible.js  │
│          api)               │ │  (YandexGPT, DeepSeek, │
│  telegram.js (задел)        │ │   Ollama, OpenRouter)  │
└─────────────────────────────┘ └────────────────────────┘
```

Экземпляр бота = `.env`:
```ini
TRANSPORT=vk            # vk | max | telegram
AI_PROVIDER=gigachat    # gigachat | openai
BOT_PERSONA=hedgehog
SKILL_PACKS=bloggers,business
```

## Слой AI-провайдеров

Контракт (то, что видит core):
```js
{
  async chat(text, { system, model }) → string
  async vision(buffer, contentType, caption, { model }) → string
  capabilities: { vision: true, filesApi: false } // чтобы скиллы знали, что доступно
}
```

- **gigachat.js** — перенос текущей логики: OAuth-токен с кэшем и 401-refresh,
  retry сетевых ошибок, CA-сертификат, Files API для фото.
- **openai-compatible.js** — один адаптер на всех: YandexGPT (OpenAI-совместимый
  режим), DeepSeek, OpenRouter, локальный Ollama/vLLM. `AI_BASE_URL` + `AI_API_KEY`
  + `AI_MODEL` / `AI_VISION_MODEL`. Vision — base64 в сообщении (без Files API).
- Выбор скиллов с учётом возможностей: если у провайдера нет vision — скилл
  «пост по фото» скрыт из меню (свойство `requires: ['vision']`).

## Слой транспортов

Нормализованный контекст, который транспорт отдаёт в core:
```js
{
  senderId: 'vk_14071149',        // префикс платформы
  peerId,
  text: '...',
  photos: [{ buffer, contentType }], // скачанные вложения (или URL — решим при реализации)
  reply(text, { keyboard }) → Promise,
  setTyping() → Promise
}
```

Контракт транспорта:
```js
{
  start(), stop(),
  onMessage(handler),        // текст и вложения
  onAction(handler)          // нажатие кнопки (callback или текст кнопки)
}
```

### Универсальная модель клавиатуры

VK и MAX устроены по-разному — модель должна покрывать обоих:

| | VK | MAX |
|---|---|---|
| Клавиатура | reply-клавиатура, «живёт» в чате | только inline, прикреплена к сообщению |
| Кнопка | текст = сообщение боту (textButton) | callback с payload (не текст) |
| Лимиты | 10 кнопок, 40 симв. | 210 кнопок / 30 рядов / 7 в ряду |

Модель: `rows: [[{ label, actionId }]]`.
- VK рендерит reply-клавиатуру; нажатие приходит как text == label.
- MAX рендерит inline callback-кнопки; нажатие приходит как `message_callback`
  с payload == actionId. Core обрабатывает оба случая через `onAction(actionId)`.
- Персистентное меню VK (клавиатура «остаётся») vs inline MAX (уходит с сообщением):
  core должен отправлять меню заново при каждом ответе для MAX — это свойство
  транспорта `keyboardStyle: 'persistent' | 'inline'`, core его учитывает.

### Специфика MAX (из документации 2026)

- Официальная библиотека `@maxhub/max-bot-api` (npm), API: `platform-api2.max.ru`
  (с 19.07.2026; старый домен отключается), **требует сертификат Минцифры в
  доверенных** — учесть в SETUP.md VDS (как и для GigaChat CA).
- Получение событий: **webhook (POST /subscriptions) — для прода**, Long Polling —
  только для разработки. Значит для прода на VDS нужны: домен, nginx с TLS,
  публичный HTTPS-эндпоинт. Это отличие от VK (там Long Poll и ничего не нужно).
- Лимит 30 rps на API — не проблема для наших нагрузок.
- Модерация бота после создания; платформа доступна юрлицам, ИП и самозанятым РФ.
- Upload фото: трёхшаговый (получить URL → загрузить бинарник → attach по token),
  изображения до 50 МБ.
- typing-статус: POST /chats/{chatId}/actions — аналог VK setActivity.
- Команды бота (до 32) через setMyCommands — слэш-команды можно регистрировать
  и там.

## Скиллы

Контракт скилла (одна запись = один сценарий):
```js
// src/skills/bloggers/style.js
{
  id: 'style_improve',
  pack: 'bloggers',
  button: 'Улучшить стиль',
  command: '/стиль',
  intents: [/^улучш(?:и|ите|ить)(?![а-яё])/i],
  requires: [],                    // ['vision'] для фотопоста
  ask: 'Пришлите текст, который нужно улучшить.',
  emptyAsk: '...',
  prompt: (text) => `Улучши стиль...: ${text}`,
  run: async (provider, input) => ... // или декларативно через prompt
}
```

Core строит из реестра: клавиатуры (по `pack`), состояния, интенты, слэш-команды.
Новый бот = новый пак скиллов + персона + `.env`. Код не меняется.

## Порядок реализации

| Шаг | Что | Оценка | Затрагивает prod |
|---|---|---|---|
| 1 | Контракт провайдера + gigachat.js адаптер | 2–4 ч | нет (рефакторинг за интерфейсом, 33 теста страховка) |
| 2 | openai-compatible.js + тесты на моках | 2 ч | нет |
| 3 | Скиллы → паки, core-движок | 3–4 ч | нет, но релиз после регресса |
| 4 | Транспортный интерфейс + vk.js (перенос текущего кода) | 2–3 ч | да, аккуратно |
| 5 | max.js (+ вебхук-сервер для прода) | 3–4 ч | нет (новый файл) |
| 6 | telegram.js (когда понадобится) | 2–3 ч | нет |

Шаги 1–3 можно смержить, не трогая рабочий VK-бот: снаружи всё остаётся прежним.
Шаг 4 — первый, кто меняет поведение прода; делаем на ветке с регресс-прогоном.

## Открытые вопросы

1. Фото в скиллах: транспорт отдаёт буфер (транспорт качает сам) или URL?
   Склоняемся к буферу в транспорте — тогда провайдер получает байты сразу.
2. MAX-прод без домена: если домена нет, webhook не поднять. Вариант — Cloudflare
   Tunnel / ngrok для старта, потом домен.
3. Регистрация бота в MAX: нужна учётка ИП/самозанятого — вне кодовой базы.
